## 摘要
多智能体工具调用正成为基于LLM系统的主导交互模式，但现有的推理框架将每次工具调用视为独立请求，从头重新处理整个对话，尽管85-95%的提示与上一轮相同。我们提出了一种状态化推理架构，将传统服务中每轮的O(n_t)成本转换为仅处理增量Δ的O(Δ_t)成本：持久化KV缓存跨轮次存活，仅通过吸收新令牌来推进；同时，基数前缀缓存将这一机制扩展到交错的多智能体流量中，而提示查找推测解码器则加速了结构化输出。在全新的全生成工作负载上，与vLLM和SGLang相比，参考实现在6轮智能体工作流中每轮速度提升2.1倍，在35轮工作流的中位轮次上提升4.2倍，端到端挂钟时间减半。这一优势来自状态化复用和推测机制，而非缓存。

## Abstract
Multi-agent tool calling is becoming the dominant interaction pattern for LLM-based systems, yet existing inference frameworks treat each tool call as an independent request, re-processing the entire conversation from scratch even though 85-95% of the prompt is unchanged from the previous turn.   We present a stateful inference architecture that converts the $O(n_t)$ per-turn cost of conventional serving into an $O(Δ_t)$ delta-only cost: a persistent KV cache lives across turns and advances by ingesting only the new tokens, while a radix prefix cache extends this across interleaved multi-agent traffic and a prompt-lookup speculative decoder accelerates structured output. Against vLLM and SGLang on novel, fully-generated workloads, the reference implementation is $2.1\times$ faster per turn on a 6-turn agentic workflow and $4.2\times$ on the median turn of a 35-turn one, halving end-to-end wall time. The advantage comes from stateful reuse and speculation, not caching.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：在多智能体工具调用场景中，现有的LLM推理框架（如vLLM、SGLang）将每次工具调用视为独立请求，从头重新处理完整对话历史。然而，在典型的多轮对话中，每轮新增的令牌仅占全部提示的5-15%，其余85-95%的令牌与上一轮完全相同。这种重复预填充造成了巨大的计算浪费，导致高延迟和低效的GPU利用率（生产集群利用率仅10-45%）。
- **整体意义**：本文提出一种**状态化推理架构**，通过持久化KV缓存、基数前缀缓存和推测解码，将每轮的计算成本从与全提示长度成正比的O(n_t)降低为仅与新增令牌成正比的O(Δ_t)。该工作为多智能体系统提供了低延迟、高效率的推理方案，有望显著降低推理集群的GPU开销和响应时间。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：让KV缓存跨请求持久存在，而不是每次重建；只在每轮处理新增的令牌；通过元数据级别的序列别名共享前缀；利用结构化输出的规律性加速生成。
- **关键技术细节**：
    - **状态化会话（Stateful Sessions）**：在单个统一推理上下文中预分配序列池（Sequence Pool），分为瞬态池和会话池，通过RAII机制管理生命周期，避免每请求分配开销。
    - **基数前缀缓存（Radix Prefix Cache）**：使用基数树管理令牌序列的前缀，将匹配的前缀通过元数据的序列别名（metadata-only sequence aliasing）在常数时间内共享到新序列的页表中，无需复制。保存时仅提交新增的增量单元。
    - **持续批处理调度器（Continuous Batching Scheduler）**：
        - 基于单元预算准入（Cell-Budget Admission），控制KV缓存占用不超过池的50%。
        - 自适应分块预填充，避免解码饥饿。
        - 前缀感知分组预填充（Prefix-Aware Grouped Prefill），将共享字节相同前缀的槽合并为一个前向传播。
        - 并发容量限定的推测解码调度（Concurrency-Capped Speculation），根据活跃解码器数量和历史接受率动态调整每槽的推测长度。
    - **渲染与分词缓存**：缓存Jinja模板渲染结果和BPE分词结果，进一步减少CPU工作。
    - **提示确定性响应缓存（Prompt-Deterministic Response Cache）**：通过FNV-1a哈希种子采样器，对完全相同的提示直接返回缓存结果（零GPU工作），用于重试、轮询等重复请求。
    - **并发容量限定的提示查找推测解码（Concurrency-Capped Prompt-Lookup Speculation）**：在当前槽的最近令牌缓冲区中查找最长的后缀匹配（n-gram），预测后续令牌，并在单次前向传播中批量验证。接受率通过指数移动平均控制，结构化输出区域接受率接近100%。
    - **流式工具调用验证器（Streaming Tool-Call Validator）**：基于括号匹配的JSON状态机，在结构闭合时提前停止生成，并过滤虚构工具名，节省20-40%的无效解码令牌。
    - **设备端贪婪采样（On-Device Greedy Sampling）**：直接在GPU上执行argmax，避免每令牌的宿主同步开销。
- **公式说明**：
    - 传统成本：\( C_{\text{standard}} = O(n_1) + \sum_{t=2}^T O(n_t) \)
    - 状态化成本：\( C_{\text{cached}} = O(n_1) + \sum_{t=2}^T O(\Delta_t) \)，其中Δ_t远小于n_t。
    - 推测解码：生成m个令牌所需的前向传播从m次降至 ⌈m/(k+1)⌉ 次，k为平均每次接受数（工具调用场景约11）。

### 6. 论文的主要结论与发现

- 状态化推理架构在新工作流上显著加速：6轮工作流每轮中位延迟2.1倍优于vLLM和SGLang；35轮工作中位数轮次上快4.2倍，端到端时间减半（31秒 vs 64秒）。
- 优势随对话深度增长而扩大，因为状态化只处理增量，而传统方法处理全量。
- 突发并发下，p99尾部延迟降低一个数量级。
- 提示确定性响应缓存对重复提示返回亚毫秒级响应（零GPU工作），是vLLM和SGLang不具备的能力。
- 所有引擎在合理生成长度下均生成有效工具调用，因此优势在于延迟而非正确性。

### 7. 优点

- **创新性**：将状态化推理（持久KV缓存）与基数树缓存、序列别名、推测解码系统性地结合，针对多智能体工具调用的特殊结构设计。
- **效率显著**：在全生成场景下实现2.1-4.2倍的延迟降低，且得益于推测解码和早期停止，生成阶段的令牌前向传播次数大幅减少。
