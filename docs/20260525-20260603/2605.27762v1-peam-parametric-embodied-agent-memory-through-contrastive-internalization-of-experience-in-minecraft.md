## 摘要
我们提出了PEAM，这是一个在Minecraft中的参数化具身智能体记忆框架，它将智能体记忆从推理时的检索转变为通过经验内化而成为参数驻留的技能。PEAM将用于开放式推理的慢速 deliberative LLM 与用于反射性执行巩固技能的快速参数化模块配对。快速模块是一种多模态的专家混合LoRA架构，具有按类别物理隔离的适配器，能够在无灾难性遗忘的情况下进行参数级别的持续学习。我们将失败视为首要的训练信号：失败-修正轨迹对通过联合行为克隆和对比目标进行内化，因此智能体不仅学习到哪些动作是成功的，还学习到修正后的动作与失败动作之间的差异。为了控制巩固过程，PEAM引入了一个参数化价值分数，用于决定哪些经验应被内化，以及一种无尺度的自触发巩固机制，用于决定何时进行内化，无需针对特定任务手动调整阈值，使得智能体在触发机制跨任务分布迁移时无需重新调整即可自我进化。在Minecraft中的实验表明，PEAM改进了长期任务性能，减轻了对先前巩固技能的遗忘，并在基于检索的具身智能体和参数化记忆变体中，提高了参数化与检索的效率对比。

## Abstract
We present PEAM, a Parametric Embodied Agent Memory framework in Minecraft that transforms agent memory from inference-time retrieval into parameter-resident skills internalized through experience. PEAM pairs a slow deliberative LLM for open-ended reasoning with a fast parametric module for reflexive execution of consolidated skills. The fast module is a multimodal Mixture-of-Experts LoRA architecture with per-category physically isolated adapters, enabling parameter-level continual learning without catastrophic forgetting. We treat failure as a first-class training signal: failure--correction trajectory pairs are internalized through a joint behavioral-cloning and contrastive objective, so the agent learns not only what succeeds but also how corrected actions differ from failed ones. To govern consolidation, PEAM introduces a parameterization-worthiness score for deciding which experience should be internalized, and a scale-free self-triggered consolidation mechanism for deciding when to internalize without task-specific hand-tuned thresholds, making the agent self-evolving as the trigger transfers across task distributions without re-tuning. Experiments in Minecraft show that PEAM improves long-horizon task performance, mitigates forgetting on previously consolidated skills, and improves parametric-versus-retrieval efficiency over retrieval-based embodied agents and parametric memory variants.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：当前 LLM 具身智能体普遍依赖**非参数化记忆**（检索式增强生成），即过去轨迹、反思等存储在外部的技能库中，每次推理时重新注入 prompt。这导致三个实际代价：上下文预算消耗、检索与 prompt 构建增加延迟、经验无法内化为智能体的参数化能力。此外，现有参数化方法（如全参数微调、单一 LoRA）面临**灾难性遗忘**问题。
- **背景**：认知神经科学认为持久记忆由两个互补系统构成：快速稀疏的**情节记忆**（编码新经验）和慢速分布式的**参数化记忆**（整合稳定结构），两者通过离线巩固耦合。PEAM 受此启发，将经验巩固视为从外部检索到参数化内化的关键路径。
- **目标**：设计一个框架，使智能体能够**自决定**哪些经验值得内化、何时内化、以及如何内化，同时避免遗忘，并提升长时任务成功率与推理效率。

## 2. 方法论

### 核心思想
- **双层架构**：慢速 deliberative LLM（π_slow，如 GPT-4o）负责开放式推理、代码生成与验证；快速参数化模块（π_fast）通过**多模态 Mixture-of-Experts LoRA（MoE-LoRA）** 架构实现反射性执行，基于 Qwen3-VL-8B-Instruct 骨干，物理隔离的每类别适配器（craft、gather、combat）。
- **经验内化**：成功轨迹（D_succ）和失败-纠正对（D_cpair）通过联合行为克隆（BC）+ 对比偏好优化（PEAM-DPO）训练，使得智能体不仅学习成功动作，还学习纠正动作相对于失败动作的差异。
- **选择性巩固**：参数化价值分数（PV）评估候选技能的内化价值（基于检索成本节省、稳定性、冗余度、类别间干扰四个维度）；自触发巩固机制（STC）基于自身失败率的统计检验（Z-test）决定何时触发更新，无需任务特定阈值。

### 关键技术细节

1. **MoE-LoRA 与物理隔离**：每个技能类别对应一个独立的 LoRA 适配器（rank=32, α=64），推理时通过路由分类器（DistilBERT）选择适配器，更新时只更新对应类别适配器，从架构上避免跨类别遗忘。
   
2. **联合损失函数**：
   \[
   \mathcal{L}_{\text{PEAM}}(\theta_c) = \mathcal{L}_{\text{BC}}(D_{\text{succ}}^{(c)}) + \lambda \cdot \mathcal{L}_{\text{PEAM-DPO}}(D_{\text{cpair}}^{(c)})
   \]
   - BC 项：标准下一个 token 负对数似然，提供绝对语法格式信号（如 JavaScript 函数包装）。
   - PEAM-DPO 项：对每对失败-纠正轨迹，以纠正轨迹为 chosen、失败轨迹为 rejected，基于冻结参考模型计算偏好损失，β=0.1。
   - λ=1.0，BC 项被证明是**负载承载**的：纯 DPO 无法生成可解析的代码（0/12 成功），联合目标则 12/12。

3. **参数化价值分数（PV）**：
   \[
   PV(s) = w_1 U_{\text{cost}}(s) + w_2 U_{\text{stab}}(s) - w_3 P_{\text{redun}}(s) - w_4 R_{\text{forget}}(s)
   \]
   - U_cost：基于 EMA 估计的未来调用频率 × 代码长度，衡量检索成本节省。
   - U_stab：成功率 × (1 - 上下文间成功方差)，奖励跨上下文稳定的技能。
   - P_redun：与已参数化技能库的最大余弦相似度（TF-IDF 嵌入），惩罚冗余。
   - R_forget：二元结构代理（1 如果与已有技能属于同一类别，否则 0），因适配器物理隔离，类别身份即代表干扰信号。
   - 权重固定（w1=0.4, w2=0.3, w3=0.2, w4=0.1），通过网格搜索确定。

4. **自触发巩固（STC）**：
   - 对于每个候选技能 s，当同时满足以下条件时触发：
     \[
     Z(s) = \frac{\hat{p}_{\text{recent}}(s) - \hat{p}_{\text{baseline}}(s)}{\sqrt{\hat{p}(s)(1-\hat{p}(s))(1/W + 1/B)}} > z_{\alpha}
     \]
     且 PV(s) 在 top-q 分位数内。
   - W=10（最近窗口），B=10（历史基线），α=0.05，q=0.5。这些是统计/结构超参数，不需要跨任务分布重调。

### 算法流程（文字说明）

- **推理阶段**：任务路由 → 若存在可用适配器，π_fast 生成代码并执行验证；若失败或无适配器，回退到 π_slow。成功或纠正后的轨迹存入情节存储 E。
- **巩固阶段**：从 E 提取候选技能，计算 PV 分数；STC 监测失败率统计，当满足触发条件时，仅更新对应类别的 LoRA 适配器 θ_c，使用联合 BC+DPO 损失。

## 3. 实验设计

- **环境与场景**：Minecraft 1.19，使用 VOYAGER 的 Mineflayer 执行框架。**11 个长时任务**，覆盖 craft（5 个）、gather（4 个）、combat（2 个）三个类别。每个任务最多 200 步，通过环境侧验证器判断成功。
- **基准对比**（8 个基线）：
  - B6: No-memory ReAct
  - B7: Reflexion（文本反思）
  - B8: MrSteve（时空记忆）
  - B3: Naive full-FT（全参数微调）
  - B4: Single shared LoRA
  - B5: EWC（弹性权重巩固）
  - B1: VOYAGER（检索式，非参数）
  - B2: Optimus-1-rep.（多模态检索式）
  - 所有方法使用相同的 Minecraft 执行接口，慢速 LLM 统一使用 Azure GPT-4o。
- **指标**：任务成功率（Wilson 95% CI）、遗忘率（按序列巩固后早期技能保留）、推理延迟（中位数每步时间）、每任务 token 消耗、触发稳健性（跨分布切片）。
- **实验数量**：
  - 主实验：11 tasks × 3 seeds = 33 trials per method。
  - 遗忘实验：craft → gather → combat 序列巩固，测量每个阶段后的保留率。
  - 消融实验：6 组消融（BC+DPO vs. DPO only；MoE 隔离 vs. 共享 LoRA；全 PV vs. 启发式；PV 留一法；STC vs. 固定计划；视觉输入权重）。
  - 触发稳健性实验：构建 craft-heavy 和 combat-heavy 两个分布切片，运行 STC 并计算 Jaccard 重叠。
  - 还有附加方法学发现（forward-pass 可部署性、量化故障等）。

## 4. 资源与算力

- **快速模块（π_fast）**：使用 **8 张 A100 80GB GPU**，bf16 精度，适配器**不合并**（hot-swap via PEFT set_adapter API），中位数每步延迟 3.2 秒。当试图部署到消费级 GPU（RTX 4070 12GB）在 4-bit 量化时出现三种失败模式（延迟过高、合并适配器零低幅度更新、token 预算不足）。
- **慢速模块（π_slow）**：Azure GPT-4o（部署版本 2024-11-20），统一用于所有方法。
- **训练**：每个适配器训练 100 步，batch size 2，gradient accumulation 8，学习率 2e-4，cosine 调度。总参数量约 83M 每适配器。

- **充分性**：论文进行了多种对比、消融和跨分布测试，覆盖了其声称的三个核心机制（成功提升、遗忘抑制、触发稳健性）。

- **可能局限**：仅在一个环境（Minecraft）中评估，任务类别有限（3 类），跨分布触发评估使用了重切片方法而非实际独立分布收集，公平性尚可但需注意合成性。遗忘实验仅测量序列中早期 craft 技能，未测量更复杂组合下的遗忘。

## 6. 主要结论与发现

- **成功率**：PEAM 在 11 个长时任务上达到 69.7%（23/33），优于 VOYAGER（54.5%，+15.2 pp, p=0.018）和最优检索式基线 Optimus-1-rep.（60.6%）。
- **效率**：中位数延迟从 5.5s 降至 3.2s（-42%），每任务 token 从 31.2K 降至 4.6K（-85%），主要得益于参数化路径消除了每次调用重新注入技能库。
- **遗忘**：在顺序巩固（craft→gather→combat）后，PEAM 保留 100% 的早期 craft 技能；而共享 LoRA 丢失 32.4%，EWC 丢失 43.3%，全微调丢失 78.5%。物理隔离适配器是遗忘抵抗的关键。
- **选择性巩固**：PV 分数显著改变候选选择（与简单启发式 Spearman ρ=-0.375），STC 在无阈值调优下跨分布产生一致触发事件（Jaccard ~0.54-0.61）。
- **方法论发现**：前向偏好边际不能预测生成路径可部署性（纯 DPO 通过边际评估但 0/12 代码可解析）；量化服务引入特有失败模式；导航任务不适合失败-纠正对比内化；轨迹重切片可作为跨分布评估的替代。

## 7. 优点

- **创新性**：将认知科学中的互补学习系统理论引入具身智能体记忆，实现了**经验向参数的主动内化**，不同于以往仅依赖外部检索或简单参数更新。
- **设计完整性**：系统性地解决了“内化什么”、“何时内化”、“如何内化”三个问题，并通过 PV 和 STC 实现**自触发、无阈值调优**，提升了跨分布适应能力。
- **遗忘抵抗**：物理隔离适配器的架构选择简洁有效，无需复杂的正则化或重放机制，在实验中表现显著优于现有参数化方法。
- **实验周密**：多个消融实验、跨分布鲁棒性测试、以及方法论发现（如量化失败模式）增加了工作的深度和实用性。
- **效率提升显著**：推理延迟和 token 消耗大幅降低，为实际部署提供了可行性。

## 8. 不足与局限

- **环境单一**：所有实验只在 Minecraft 中进行，通用性未知。声称的“遗忘抵抗”、“触发稳健性”等有待在其他领域（如机器人操作、网页智能体）验证。
- **技能类别有限**：只有 3 个巩固类别（craft、gather、combat），适配器数量线性增长，未测试大规模类别增多时的扩展性。
- **动作空间限制**：使用 JavaScript 动作语法（VOYAGER 格式），BC 项的必要性可能因不同语法而异。
- **PV 权重固定**：通过网格搜索固定，未探究自适应权重或元学习调整。
- **跨分布触发评估局限**：使用轨迹重切片而非独立分布收集，存在合成性与真实分布之间的差距。
- **遗忘测试范围窄**：仅测量序列化类别的早期技能，未测试非序列化或交互性遗忘（如同时巩固不同类别后的再迁移能力）。
- **计算资源门槛较高**：快速模块需要 8 张 A100 才能获得良好延迟，量化部署存在兼容性问题，实际边缘部署困难。
- **未报告完整的 GPU 小时数**，但训练规模较小（每适配器 100 步），可能不是主要限制，但缺乏量化基准。
