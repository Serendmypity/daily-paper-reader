## 摘要
对于使用工具的LLM智能体，多轨迹推理（生成多个推理尝试并从中选择）受益于在尝试之间传递知识，以便后续尝试避免早期尝试的陷阱。现有的跨轨迹记忆方法（轨迹级反思、原子事实提取、原始观察注入）均在不同任务上的单一推理策略下进行评估，这使得报告的性能提升是反映了记忆抽象的特性还是推理方法的特性变得不明确。我们提出了一个统一框架，沿两个轴分解记忆——迁移范围（在扩展内 vs. 跨轨迹）和迁移内容的抽象程度——并在四种工具使用基准（涵盖SQL、知识图谱和CLI环境）上，在无验证器设置下（与实用智能体的部署模式匹配），评估了三种推理策略（最佳N、波束搜索、MCTS）下的四种方法。实验矩阵将推理方法识别为混杂因素：相同的记忆方法在不同推理策略下对相同示例会产生统计上不同的结果。反思仅在MCTS下达到显著性（在最佳N下不显著）；扩展内注入（根据先前兄弟结果对每个候选进行条件化）仅有助于多样性匮乏的波束搜索；而原子事实提取对准确性无影响，但在具有可复用环境结构的任务上使轨迹长度缩短19-26%。

## Abstract
Multi-trajectory inference for tool-use LLM agents - generating multiple reasoning attempts and selecting among them - benefits from transferring knowledge across attempts so that later ones avoid the pitfalls of earlier ones. Existing cross-trajectory memory methods (trajectory-level reflection, atomic fact extraction, raw observation injection) are each evaluated under a single inference strategy on a single task, making it unclear whether reported gains reflect properties of the memory abstraction or of the inference method. We propose a unified framework that decomposes memory along two axes -- the scope of transfer (within an expansion vs. across trajectories) and the abstraction of the transferred content -- and evaluate four methods under three inference strategies (best-of-N, beam search, MCTS) on four tool-use benchmarks spanning SQL, knowledge-graph, and CLI environments, in a verifier-free setting that matches the deployment regime of practical agents. The experiment matrix identifies the inference method as a confound: the same memory method produces statistically distinct results under different inference strategies on the same examples. Reflection reaches significance only under MCTS (not under best-of-N); within-expansion injection (conditioning each candidate on prior siblings' outcomes) helps only diversity-starved beam search; and atomic fact extraction is accuracy-neutral but shortens trajectories by 19-26% on tasks with reusable environmental structure.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
将记忆机制沿两个正交轴分解：
- **传递范围（Scope）**：
  - **跨兄弟（within-expansion）**：在同一节点的多候选扩展中，每个候选看到先前兄弟候选的动作和观察结果。
  - **跨轨迹（cross-trajectory）**：记忆从之前完整的轨迹（或迭代）中提取并传递给后续轨迹。
- **内容抽象（Abstraction）**：
  - **原始（Raw）**：无处理直接注入原始动作-观察对。
  - **反思（Reflection）**：LLM生成的轨迹级策略总结。
  - **原子事实提取（Atomic Fact Extraction）**：LLM从观察中提取离散的、可复用的环境事实，并通过嵌入相似性去重。

### 技术流程（附录H）
1. **触发**：搜索循环中的事件（步骤完成、轨迹完成）触发增强器。
2. **分析**：增强器根据历史生成上下文单元（策略意见、结构化事实等）。

4. **检索与注入**：在动作采样前，将相关上下文注入策略提示中。

### 推理策略
- **Best-of-N**：顺序生成N条轨迹，记忆将i.i.d.采样转为条件化尝试。
- **Beam Search**：每步保留B个候选，记忆在每一步作用于跨兄弟分支。
- **MCTS**：选择-扩展-模拟-反向传播，记忆同时作用于扩展（步级）和反向传播（轨迹级）。

### 无验证器设置（verifier-free）
论文采用**无在线二元验证器**的设置（任务验证仅在评估时离线进行），更符合实际部署场景。这与以往依赖在线验证器（如精确匹配、单元测试）的工作不同，避免了验证器信号混淆记忆效果。

## 6. 论文的主要结论与发现

### 发现1（F1）：记忆的准确性效果依赖推理策略
- **反思（Reflection）**：仅在MCTS下达到统计显著性（WikiSQL: p=0.031; KGQA: p=0.039）；在Best-of-N下不显著。原因：MCTS中每步奖励模型可过滤反思引入的错误路径，而Best-of-N无此机制。
- **跨兄弟注入（Raw Sibling）**：仅对**多样性匮乏的波束搜索**有显著提升（KGQA Beam: +20.3pp, p=0.003）；对MCTS无增益（因UCT已提供足够多样性）。

### 发现2（F2）：在KGQA MCTS上，不同记忆抽象收敛
- 尽管Reflection和Raw Sibling在作用范围（跨轨迹 vs. 跨兄弟）和抽象级别（策略总结 vs. 原始观察）上完全不同，但在KGQA MCTS下两者准确率完全相同（34.8%），且9/10的挽救例重叠。这意味着在这个难点子集上，只要能打破i.i.d.采样，任何非独立上下文都能恢复，抽象选择不再重要。

### 发现3（F3）：原子事实提取不提升准确率，但缩短轨迹长度
- LiTS-Fact在所有测试单元格上的准确率效应均为零（McNemar p≥0.25）。
- 但在具有可复用环境结构的任务上（SQL / KGQA），它使平均轨迹长度缩短 **19-26%**（例如WikiSQL从6.1步降至4.9步），因为后续尝试可跳过初始的表/关系发现步骤。
- 轨迹缩短的机制：跳过`sql_db_list_tables`等调用，在尝试1-4中跳过率从4-5%升至70-77%。
- 组合反射+事实时，精度和效率反而下降，因反射提供的显式计划覆盖了事实记忆的隐含快捷方式。

## 7. 优点：方法或实验设计上的亮点

- **统一框架**：首次将记忆机制的评估分解为范围×抽象两个正交轴，为后续系统化研究提供了理论工具。
- **控制推理策略这一混杂因素**：通过在相同示例上对比同一记忆方法在不同推理策略下的表现，揭示了推理策略是重要的干扰变量，这是被以往工作忽略的。
- **verifier-free设置**：更贴近实际部署中无法获得在线正确性信号的情况，增强了结论的实用价值。
- **统计检验严谨**：使用McNemar exact配对检验，报告确切p值及抢救/回归数，避免仅依赖准确率差值。
- **开源性**：基于LiTS框架，将开源记忆模块和配置，有利于复现和扩展。
- **消融深入**：通过案例跟踪（如WikiSQL例26、例29）验证了反思的MCTS机制；对事实提取失败进行详细机制分析（附录M），诚实报告副作用。

## 8. 不足与局限

### 实验覆盖
- **单一政策模型**：每个基准仅使用一个LLM（Haiku 3.5或Sonnet 4.6），未考察不同采样行为模型对记忆效果的影响。例如，若模型本身多样性较高，Raw Sibling可能不再必要。
- **样本量较小**：KGQA的69子集、SQL基准的49-51样本量，对于检测≤6pp的效应可能功率不足。作者也承认这一点。
- **未覆盖跨任务记忆**：本文仅研究单任务实例内的跨轨迹记忆，未涉及知识在多个不同任务间的迁移（如ExpeL），这是一类重要的未来方向。
- **仅评估非选择性检索**：LiTS-Fact使用"注入全部事实"策略，选择性检索可能影响结果，但附录O论证了选择性检索无法解决多样性-效率权衡。不过该论证是理论性的，缺少实证支持。

### 风险与限制
- **商业化API成本**：总成本约$1,384，且需多次API调用（MCTS中每步需奖励模型），限制了大规模消融和复现的可行性。
- **组合记忆的负面效应**：反射+事实组合出现精度与效率双降，说明不同抽象级别记忆可能相互干扰，部署时需谨慎集成。
- **非序列化环境覆盖不足**：仅Terminal-Bench一种非序列化环境，且该环境下仅测试了Best-of-N（无法使用波束搜索/MCTS），记忆效果在非序列化场景下的结论较弱。
- **反思仅MCTS有效的普遍性**：此结论基于SQL/KGQA两个基准，且反思在WikiTQ上未达显著性（可能低功率），因此该模式是否在所有工具任务中成立需进一步验证。
