## 摘要
将大型语言模型训练为检索增强的推理代理通常会将强化学习与从更强模型精馏得到的SFT冷启动相结合。然而，这种范式忽视了子技能之间的依赖结构以及蒸馏并非获取能力的唯一途径这两个基本因素。我们通过“计划”（Plan）来研究这一点，这是一种用于多跳检索的结构化代理行为，它在任何检索执行之前将问题分解为有序的子问题，从而使得每个搜索步骤可以锚定在预先设计的子问题上，而不是在先前检索到的部分相关文档的影响下偏离方向。然而，在跨越3B到14B参数的三个模型家族中，我们发现相同的奖励信号会诱导出性质不同的强化学习失败模式。这一现象表明，成功的训练不仅取决于奖励设计，还取决于模型特定的可行性条件：足够的初始熵、训练稳定性以及必备的子技能。受此启发，我们提出了一种自举范式，其中一个小规模的种子模型生成过滤后的轨迹，从而在任何目标模型中激活“计划”，消除了从外部更强模型进行蒸馏的需要。我们的流程在所有测试的模型中均能激活“计划”，并在多跳问答基准测试中持续优于竞争基线。

## Abstract
Training large language models as retrieval-augmented reasoning agents typically combines reinforcement learning with an SFT cold start distilled from a stronger model. However, this paradigm overlooks two fundamental factors: the dependency structure among sub-skills, and the possibility that distillation is not the only route to capability acquisition. We study this through Plan, a structured agentic behavior for multi-hop retrieval that decomposes a question into ordered sub-questions before any retrieval is performed, so that each search step can be anchored to a pre-designed sub-question instead of drifting under the influence of partially relevant documents retrieved earlier. However, across three model families spanning 3B to 14B parameters, we find that an identical reward signal induces qualitatively different RL failure modes. This phenomenon indicates that successful training hinges not only on reward design but also on model-specific feasibility conditions: sufficient initial entropy, training stability, and prerequisite sub-skills. Motivated by this, we propose a self-bootstrapping paradigm in which a small-scale seed model generates filtered trajectories that activate Plan in any target model, eliminating the need for distillation from an external stronger model. Our pipeline activates Plan across every tested model and consistently outperforms competitive baselines on multi-hop QA benchmarks.

## 1. 核心问题与整体含义（研究动机与背景）

当前训练检索增强推理代理的主流范式是“强化学习 + 从更强模型蒸馏的SFT冷启动”。但该范式忽视了两个关键因素：
- **子技能间的依赖结构**：复杂行为（如多跳检索中的“计划”）需要协调多个子技能，这些子技能并非独立，而是存在顺序依赖关系。
- **蒸馏并非唯一路径**：是否一定需要外部更强模型来提供冷启动数据？小模型能否通过自身探索习得能力？

论文以“计划”（Plan）作为研究载体——即在检索前先将问题分解为有序子问题，再逐步骤执行。该行为能有效防止搜索轨迹因部分相关文档累积而漂移。但作者发现，相同的奖励信号在不同模型家族（Qwen2.5、Llama3.2、Qwen3）和规模（3B–14B）上会诱导出**性质不同的RL失败模式**，揭示出训练成功不仅依赖奖励设计，更取决于**模型特定的可行性条件**（初始熵、训练稳定性、前置子技能）。在此发现基础上，论文提出**自举（self-bootstrapping）训练范式**，用小种子模型生成的过滤轨迹替代外部蒸馏，从而激活任意目标模型的计划能力。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- **Plan行为形式化**：对多跳问题q，模型首先生成全局计划块`<plan>`，列出有序子问题（Step 1, Step 2, ...）；然后依次执行每个子问题的“思考→搜索→文档→精炼”步骤，最后给出答案。每一步的思考都明确锚定到对应的子问题，避免搜索漂移。
- **计划感知奖励函数**：
  - \( R = R_{\text{ans}} + I[R_{\text{ans}} = 0] \cdot R_{\text{aux}} \)
  - 结果奖励\(R_{\text{ans}}\)：答案F1分数。
  - 辅助奖励\(R_{\text{aux}} = \lambda_{\text{fmt}} R_{\text{fmt}} + \lambda_{\text{plan}} R_{\text{plan}}\)，仅在预测答案与真实答案无重叠时激活。
    - 格式奖励\(R_{\text{fmt}}\)：检查标签完整性及搜索前必须有思考。
    - 计划奖励\(R_{\text{plan}}\)：计算计划子问题与对应思考块的平均token F1，并通过阈值函数（\(\delta=0.25\)）防止模型直接复制计划内容。

### 自举训练流程
1. **种子模型构建**：选择Qwen2.5-3B-Base作为种子（满足可行性条件）。先通过AutoRefine式RL训练获取“精炼”技能，再在其基础上进行Plan RL训练，得到π_seed。
2. **轨迹生成与过滤**：用π_seed在训练集上生成轨迹，经硬过滤（格式正确且答案匹配）和软过滤（搜索轮次、查询多样性、精炼密度综合评分）后，桶采样得到4500条高质量轨迹。
3. **激活目标模型**：对任一目标模型（base或instruct），先在此4500条轨迹上SFT 3个epoch，再使用完整计划感知奖励进行RL精炼。

## 6. 主要结论与发现
1. **直接RL训练Plan会因模型特性而以不同方式失败**：低初始熵导致“先验崩溃”；训练稳定性不足导致“熵爆炸”；缺乏前置“精炼”技能导致训练崩溃。
2. **SFT冷启动之所以有效，是因为它将模型策略重置到具备适当熵、稳定性及前置技能的可行区域**。
3. **自举范式可行且优于蒸馏**：小种子模型生成的过滤轨迹能激活任意目标模型的Plan能力，且性能超过使用更大（72B）模型蒸馏的数据。关键在于**轨迹需位于目标模型的可达分布内**。
4. **Plan行为在多跳QA上带来显著提升**：在12种模型配置上，MH-Avg平均提升0.053；总平均EM（3B）达到0.430（Base）和0.432（Instruct），超越最强基线。

## 7. 优点
- **问题洞察深刻**：识别出子技能依赖和模型特定可行性条件，解释了SFT冷启动为何如此普遍有效，而不仅仅是经验性的。
- **方法简洁且高效**：自举范式消除了对外部强模型蒸馏的依赖，仅需一个3B种子模型即可激活所有目标模型，具备实用价值。
- **奖励设计精细**：计划奖励采用阈值化设计防止奖励黑客，格式奖励确保行为结构，且辅助奖励仅在答案错误时激活，避免干扰正确轨迹。
- **实验覆盖广泛**：横跨三个模型家族、多个规模，并系统展示了不同失败模式，结论具有普遍性。
- **分析深入**：通过对熵和批评家分数动态的跟踪，直观揭示了RL训练的不稳定性根源。

## 8. 不足与局限
- **任务范围有限**：仅聚焦于多跳问答中的“计划”行为，未拓展到工具选择、长时规划等其他代理任务，泛化性需进一步验证。
- **检索环境静态**：使用2018年Wikipedia快照（如Search-R1和AutoRefine），非实时网络检索，可能无法反映动态、对抗性检索条件下的行为。
- **培训数据量较小**：SFT数据仅4500条，虽然够用，但更大量数据的缩放效果未充分探索（表7显示增益已饱和）。
- **潜在分布偏差**：种子模型Qwen2.5-3B-Base的选择可能引入偏差，其他家族中是否一定存在类似种子需进一步验证。
- **计算成本**：虽然自举避免了大型教师模型，但种子模型需两阶段RL训练，每个目标模型又需SFT+RL，整体算力开销在资源受限场景下可能仍显昂贵。
