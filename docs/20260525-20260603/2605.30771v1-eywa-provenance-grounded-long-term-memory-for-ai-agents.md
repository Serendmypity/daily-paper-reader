## 摘要
需要在会话间持久化的AI代理需要能够检索、审计、更新和擦除的记忆。现有的记忆系统往往将源证据、提取的事实、检索到的上下文和答案策略合并为一条不透明的提示路径，使得故障难以诊断：错误答案可能源于证据缺失、不支持提取、状态陈旧、检索丢失或答案模型行为。我们提出Eywa，一种围绕“先证据后信念”构建的基于来源溯源的记忆架构。Eywa在推导规范事实之前存储不可变的源证据，根据类型化信号和源支持验证提取的记忆，并通过确定性多路读取路径（检索内部无需LLM调用）检索有界的记忆上下文。检索到的上下文与答案指令分开返回，允许跨前沿、预算和本地答案模型评估相同的记忆基底。在冻结且记录工件的检索配置下，Eywa在LoCoMo C1-C4分割上使用Claude Sonnet 4.6写入和问答角色达到90.19%的判断准确率。在LongMemEval-S上达到88.2%的检索充分性准确率。在BEAM（一个700问题的技术记忆压力基准）上达到81.45%的平均金块分数和85.29%的通过分数>=0.5。完整的每问题工件（包括问题、黄金答案、模型答案、检索上下文和标签）已发布于https://eywa.to/research。

## Abstract
AI agents that persist across sessions need memory they can retrieve, audit, update, and erase. Existing memory systems often collapse source evidence, extracted facts, retrieved context, and answer policy into one opaque prompt path, making failures difficult to diagnose: a wrong answer may come from missing evidence, unsupported extraction, stale state, retrieval loss, or answer-model behavior. We present Eywa, a provenance-grounded memory architecture built around evidence before belief. Eywa stores immutable source evidence before deriving canonical facts, validates extracted memories against typed signals and source support, and retrieves bounded memory context through a deterministic multi-route read path with zero LLM calls inside retrieval. Retrieved context is returned separately from answer instructions, allowing the same memory substrate to be evaluated across frontier, budget, and local answer models. Under a frozen, artifact-recorded retrieval configuration, Eywa reaches 90.19% judge accuracy on the LoCoMo C1-C4 split with Claude Sonnet 4.6 write and QA roles. On LongMemEval-S, it reaches 88.2% retrieval-sufficiency accuracy. On BEAM, a 700-question technical-memory stress benchmark, it reaches 81.45% mean nugget score and 85.29% pass@score >= 0.5. Full per-question artifacts, including questions, gold answers, model answers, retrieved context, and labels, are published at https://eywa.to/research.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题现状**：现有AI代理记忆系统常将源证据、提取的事实、检索到的上下文和答案策略混入一条不透明的提示路径中，导致错误难以诊断。一个错误答案可能源于证据缺失、提取不准确、状态陈旧、检索丢失或答案模型行为等多种原因，但现有系统无法区分这些层次。
- **研究动机**：需要一种可审计、可追溯、可分离的记忆架构，使得记忆系统的每个环节（写入、提取、检索、回答）可以独立检查和改进，从而实现更高的透明度和可靠性。
- **整体意义**：Eywa提出了“证据先于信念”的溯源记忆架构，将不可变的源证据与导出的信念分离，并在读取路径上实现确定性零LLM检索，从根本上改变了AI代理记忆的设计范式。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
- **证据先于信念**：所有记忆操作基于不可变的源证据，导出的事实（信念）必须经过验证并链接回源证据。
- **分离原则**：证据与信念分离、检索与回答合成分离、策略与记忆存储分离。

### 2.2 写路径（写入路径）
- **Tier 0：不可变捕获**：每个用户指令存储为不可变证据行；信号检测器（基于规则，无需LLM）提取类型化锚点（日期、实体、金额、版本号、URL等）。
- **Tier 1：验证提取**：LLM从证据窗口提取候选事实，通过验证函数 \( V(\hat{f}, E, S) \) 检查：
  - 支持度（\( V_{support} \)）：词汇和模糊重叠验证
  - 硬锚点（\( V_{hard} \)）：确定性值匹配
  - 主体（\( V_{subject} \)）：声称主体是否在支持窗口或已知实体中
  - 行为（\( V_{act} \)）：保留否定和不确定性
- 验证通过的事实成为规范事实，保留到源证据的来源链接。

### 2.3 记忆表示与来源
- 使用来源图存储：证据记录为不可变根，信号为类型化注释，规范事实为导出信念，并通过来源元数据连接。
- 实现：SQLite权威存储 + LanceDB向量索引 + SQLite FTS5关键词索引 + 图关系。

### 2.4 提取模式
- 规范（Canonical）、观察（Observation）、混合（Hybrid）、结构化技术提取（Structured Technical），支持不同召回率与精度权衡。

### 2.5 读路径：确定性多路检索
- **零LLM调用**：从接收查询到返回上下文，全程无LLM调用。
- **确定性查询规划器**：基于问题形状（精确、推荐、推理、计数、时间、布尔、列表、事实）及时间/线索分配通道权重。
- **检索通道**：向量（余弦相似度）、关键词（BM25+查询扩展）、时间（日期范围）、实体/图（遍历知识图谱）。
- **融合**：加权倒数秩融合（加权RRF）
  \[
  RRF(f) = \sum_{c \in C} \frac{w_c}{k + \text{rank}_c(f)}
  \]
  其中 \( k=20 \)。
- **后融合过滤器**：人员降权因子（\( \delta_p=0.05 \)）、保留底线（\( r_{\min}=25 \)）保护有效候选不被淹没。
- **路线保留与救援**：对于精确、列表、计数等类型，启用原始段落救援通道。
- **上下文打包**：在预算令牌数下，按排名和实体分组打包为上下文字符串 \( \mathcal{C}_q \)。

### 2.6 答案策略分离
- 读返回包含 `context`（检索证据）和 `answer_instructions`（策略文本）两个独立字段。
- 三种模式：strict（仅直接证据）、balanced（允许隐含）、advanced（允许谨慎推理和常识桥梁）。
- 同一检索架构可服务于不同能力和策略的答案模型。
