## 摘要
LLM智能体日益需要在需要不同执行范式的异构任务场景中运行。这挑战了固定智能体系统，并促使系统级元适应超越孤立组件更新。虽然现有工作已适应外部驾驭框架或训练底层推理策略，但全系统适应仍未得到充分表征。结构与执行之间的适应空间很少被明确，外部驾驭框架与内部推理器之间的兼容性也未得到联合优化。我们提出HarnessForge，一种用于演化LLM智能体系统的元自适应框架。HarnessForge将智能体系统形式化为驾驭框架-策略对，定义了一个稳定的适应空间，将驾驭框架级别的执行结构与策略级别的推理行为分离。随后，通过故障引导的驾驭框架裁剪和框架条件化的策略对齐，进行驾驭框架-策略协同进化。跨五个不同领域基准的实验表明，HarnessForge一致地改进了Qwen3-4B和Qwen3-8B骨干网络，优于仅驾驭框架和仅策略的基线，性能比最强基线提升高达12.0%，并实现了有利的部署效率权衡，证明驾驭框架-策略协同进化是有效的，且驾驭框架与推理策略之间的可执行兼容性对于智能体系统适应至关重要。代码可在https://github.com/mingju-c/HarnessForge获取。

## Abstract
LLM agents are increasingly expected to operate across heterogeneous task regimes that require distinct execution paradigms. This challenges fixed agent systems and motivates system-level meta-adaptation beyond isolated component updates. While existing works have adapted external harness or trained underlying reasoning policies, full-system adaptation remains insufficiently characterized. The adaptation space between structure and execution is rarely made explicit, and the compatibility between the external harness and the internal reasoner is not optimized jointly. We propose HarnessForge, a meta-adaptive framework for evolving LLM agent systems. HarnessForge formulates an agent system as a harness--policy pair, defining a stable adaptation space that separates harness-level execution structure from policy-level reasoning behavior. It then performs harness--policy co-evolution through fault-guided harness tailoring and harness-conditioned policy alignment. Experiments across five benchmarks from diverse domains show that HarnessForge consistently improves both Qwen3-4B and Qwen3-8B backbones, outperforming harness-only and policy-only baselines with gains of up to 12.0\% over the strongest baseline and achieving favorable rollout-efficiency tradeoffs, demonstrating that harness--policy co-evolution is effective, and that executable compatibility between the harness and reasoning policy is essential for agent-system adaptation. The code is available at https://github.com/mingju-c/HarnessForge.

- **研究动机**：作者指出，LLM智能体系统是一个耦合的“驾驭框架-策略对”（harness–policy pair），外部驾驭框架提供结构支持，内部策略需学会在该框架下执行。若仅优化一方，可能出现兼容性鸿沟：更复杂的驾驭框架可能因推理器无法可靠执行而失败；更强的策略可能受限于不合适的驾驭框架暴露的状态、行动或控制信号。因此需要联合进化二者。
- **整体含义**：提出HarnessForge框架，将系统级适应重新定义为驾驭框架-策略对的联合进化，以提升二者间的可执行兼容性，实现任务场景自适应的元适应。

## 2. 论文提出的方法论

### 核心思想
将LLM智能体系统形式化为一对：`G = (H, Rδ)`，其中：
- `H = (P, A, M)` 是外部可编辑的驾驭框架，包含规划组件（P）、动作组件（A）和记忆组件（M）。
- `Rδ` 是适配后的推理策略，由基础推理器 `Rθ0` 加上轻量适配器 `δ` 组成。
- 适应空间被明确划分为驾驭框架级别的执行结构和策略级别的推理行为。

### 关键技术细节
**元适应联合进化**：每轮迭代包含两个阶段：
1. **故障引导的驾驭框架裁剪（Fault-Guided Harness Tailoring）**：
   - 对当前种群中的每个智能体系统执行任务批次，收集轨迹和评估向量。
   - 使用元智能体进行**故障归因（Fault Attribution）**，将故障定位到规划、动作或记忆组件。
   - 从历史档案 `Z(r)` 中检索相关的 Pareto-最优示例，生成**改进报告（Improvement Report）**。
   - 基于改进报告生成 `Kgen` 个候选驾驭框架，通过分阶段 Pareto 筛选（预算化半选）选择幸存者。
2. **框架条件化的策略对齐（Harness-Conditioned Policy Alignment）**：
   - 对每个幸存驾驭框架，继承其父代策略，训练一个特定于该框架的 LoRA 适配器
   - 复用驾驭框架筛选阶段已收集的成功轨迹（无需额外采样），构建决策对数据集 `DHk`。
   - 使用监督微调（SFT）作为默认目标，也可替换为 GRPO、RLOO 等 RL 目标（论文证明训练目标无关性）。

**轮次结构**：每轮交替进行驾驭框架进化和策略进化，种群逐步产生更适应的系统。

### 算法流程（文字说明）
- 初始化：基础驾驭框架 + 冻结基础推理器 → 单一种群。
- 每轮 r：
  1. 对每个父代对执行任务批次收集轨迹。
  2. 生成故障报告，检索档案案例，产生改进摘要。
  3. 生成 Kgen个子代驾驭框架，通过接口和冒烟测试丢弃无效项。
  4. 分阶段 Pareto 筛选幸存者（默认保留2个）。
  5. 对每个幸存驾驭框架，复用其成功轨迹，从父代策略克隆并训练新适配器。
  6. 返回匹配对（H, Rδ）进入下一轮。

## 6. 论文的主要结论与发现

1. **联合进化有效**：HarnessForge 在所有基准上持续超越仅驾驭框架或仅策略的基线，平均提升 3.56%，最高 12.0%。
2. **兼容性关键**：匹配的驾驭框架-策略对显著优于非匹配组合；后期策略与早期驾驭框架搭配性能下降，表明兼容性增益是成对特定的。
3. **滚部署效率**：HarnessForge 始终处于 Pareto 前沿，比纯策略训练方法（如 GRPO）用更少滚部署达到更高性能。
4. **训练方法无关**：SFT、GRPO、RLOO 均可作为策略对齐目标，SFT 是默认高效选择，RL 方法可进一步提升但成本更高。
5. **驾驭框架进化是主导因素**：消融实验表明移除驾驭框架进化的性能下降远大于移除策略进化。
6. **可迁移性**：在 ToolHop 上演化的驾驭框架可迁移至 TMDB 和 API-Bank 等新 API 环境。
